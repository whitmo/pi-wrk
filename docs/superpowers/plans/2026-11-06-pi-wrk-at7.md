# @@7 Message Intake Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver @@7 comments and eligible terminal messages to a background pi-wrk triager without disturbing the existing Zellij watch.

**Architecture:** Two TypeScript collectors read Git-changed work files and eligible Zellij tabs on the next Pi turn. The extension submits one background agent job per intake, retains seen keys in the Pi session, and displays its result in the transcript without starting another turn. The triager acts in its own worktree on independent changes; dirty-file changes return to the worktree owner.

**Tech Stack:** Node.js, TypeScript (Pi extension), Git, Zellij, node:test, existing pi-wrk store and worker.

**Spec:** `docs/superpowers/specs/2026-11-06-pi-wrk-at7-design.md`

## Global Constraints

- Default scope is changed files in the agent's own worktree, not the whole repository. Explicit whole-repo intake is available on request.
- A terminal tab is eligible only when the agent created, visited, or explicitly named it. A user's focus switch alone does not qualify.
- The current `/watch:zellij` behavior and explicit watches must remain unchanged.
- An @@7 message may ask, request an action, or give feedback; it is not elevated authorization.
- The extension collector is TypeScript-native; do not call a Python collector.
- Background triage must not edit a worktree owner's dirty files directly. Commit independent actions in an isolated worktree and report the commit.
- Render answers in Pi's transcript without triggering a turn. Do not insert source comments to answer.

## Review Focus

- A staged, unstaged, or untracked comment must be detected, but an unchanged old @@7 in an otherwise edited file must not be reclassified (Task 1 test).
- A repeated marker must not create a second job after Pi reloads the same session (Task 3 test).
- A shell echo/history reference to @@7 is not a terminal message (Task 2 test).
- An unrelated user tab switch must not expand the eligible tab set (Task 2 test).
- A session switch during asynchronous collection must not submit a job to the old or new owner's session (Task 3 test).

### Task 1: File collector

**Files:**
- Create: `extensions/at7-files.ts`
- Test: `tests/at7-files.test.mjs`

**Interfaces:**
- Produces: `At7Message = { key: string; source: 'file' | 'zellij'; location: string; text: string }` (exported type).
- Produces: `collectFileMessages(root: string, scope: 'changed' | 'all', seen: ReadonlySet<string>): Promise<At7Message[]>`.
- `location` is `relative/path:line`; `key` includes source, location, and marker text. Return only new keys; caller records them after job admission.

- [ ] **Step 1: Write failing behavior tests.** In a temporary Git repo, assert staged, unstaged, and untracked @@7 comment lines are returned; changing an adjacent non-marker line does not return an older committed @@7. Assert no duplicate if its key is in `seen`; explicit `all` reads tracked and untracked files; ordinary prose and code strings containing @@7 do not match. Include a spaced path and ignore Git-ignored files.
- [ ] **Step 2: Run `node --test tests/at7-files.test.mjs`.** Expect failing import or assertions.
- [ ] **Step 3: Implement `collectFileMessages` in `extensions/at7-files.ts`.** Use Git's NUL-delimited path listing and `git diff HEAD --unified=0` additions for staged/unstaged tracked files; read untracked files as a whole. `all` is explicit. Parse comment-leading markers (`#`, `//`, `--`, `/*`, `*`, `<!--`) with same-line text; skip binary/unreadable files. No Python subprocess.
- [ ] **Step 4: Rerun `node --test tests/at7-files.test.mjs` and `npx tsc --noEmit`.** Expect pass.
- [ ] **Step 5: Commit the tested collector.**

**Interfaces:**

### Task 3: Background triage and transcript delivery

**Files:**
- Modify: `extensions/index.ts`
- Modify: `tests/extension.test.mjs`

**Interfaces:**
- Consumes: both collectors' `At7Message[]`.
- Produces: a single pi-wrk `agent` request per intake. The agent prompt includes source/location/text, permitted independent action in its own worktree, and dirty-file handback. `/wrk at7 scan --all` explicitly uses the whole-repo scope. Seen keys persist via `pi.appendEntry('wrk-at7-seen', { keys })` after durable admission; read them from the current branch on session start.
- Produces: `pi.sendMessage({ customType: 'wrk-at7', content: result, display: true }, { triggerTurn: false })` for completed triage jobs. Do not alter `lastRootId` or the user's conditional job chain.

- [ ] **Step 1: Write failing extension tests.** On `before_agent_start`, assert one admission with eligible source lines, with correct cwd and owner; no admission on repeat or after same-session reload. Assert a session switch while awaiting collection drops stale results. Assert the triager's success/failure report is displayed without triggering a new turn and that unrelated wrk notices remain unchanged. Test dirty-file ownership and independent-worktree instructions by inspecting the composed prompt during direct verification, not by freezing static wording in a test.
- [ ] **Step 2: Run `node --test tests/extension.test.mjs`.** Expect failure.
- [ ] **Step 3: Wire collection, admission, seen entries, and result delivery.** Use the existing `admitNamed`, worker, owner, and notice timer. Treat collector failure as a visible warning without suppressing the user's turn; do not wake on marker arrival. Show a bounded result in transcript with job label for full `/wrk status` lookup.
- [ ] **Step 4: Run the extension tests and `npx tsc --noEmit`.** Expect pass.
- [ ] **Step 5: Commit the tested integration.**
